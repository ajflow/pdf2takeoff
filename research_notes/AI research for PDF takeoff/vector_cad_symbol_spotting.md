## Q1. State of the art on FloorPlanCAD and successors (CADTransformer, GAT-CADNet, SymPoint, SymPoint-V2, CADSpotting, DPSS, VecFormer, 2026 work): PQ/F1, model size, inference cost

### Takeaway
Vector-native panoptic symbol spotting on FloorPlanCAD went from PQ ~56-60 (2021) to 91.1 (VecFormer, NeurIPS 2025) in four years; the field has now split into "with layer/color prior" vs "no prior" settings, and the no-prior setting (the one that matches a PDF, which usually has no CAD layers) tops out around 86-88 PQ. 2026 work (TextCAD, PolarSym, TempFit) is incremental (+1-2 PQ) or changes the metric; all models are 35M+ parameter GPU models with custom point/sparse ops, and none publish browser-relevant latency.

### Cited Findings

Lineage and headline numbers (FloorPlanCAD test set, PQ = RQ x SQ):

| CADTransformer | CVPR 2022 | 68.5 (paper) / 68.9 (later tables) | 88.3 / 73.3 | >65M | ViT on primitive tokens |
| GAT-CADNet | CVPR 2022 | 73.7 | 91.4 / 80.7 | n/r | graph attention |

- **FloorPlanCAD baseline PanCADNet reported PQ 0.561** on the test set — [FloorPlanCAD, Fan et al., ICCV 2021](https://arxiv.org/abs/2105.07147). CADTransformer cites the prior SOTA as 0.595 and lifts it to 0.685 — [CADTransformer, CVF](https://openaccess.thecvf.com/content/CVPR2022/html/Fan_CADTransformer_Panoptic_Symbol_Spotting_Transformer_for_CAD_Drawings_CVPR_2022_paper.html) (the 56.1 vs 59.5 discrepancy is between the dataset paper and later tables; unresolved).
- **CADTransformer: Panoptic Symbol Spotting Transformer for CAD Drawings** — Zhiwen Fan, Tianlong Chen, Peihao Wang, Zhangyang Wang (UT Austin), CVPR 2022, pp. 10986-10996. ViT backbone whose tokens are the graphical primitives; neighborhood-aware (kNN) self-attention, hierarchical aggregation, graphic-entity position encoding; two heads (semantic + instance); "Random Layer" augmentation that separates and recombines drawings by CAD layer. PQ 0.595 -> 0.685 — [CVF open access](https://openaccess.thecvf.com/content/CVPR2022/html/Fan_CADTransformer_Panoptic_Symbol_Spotting_Transformer_for_CAD_Drawings_CVPR_2022_paper.html); code VITA-Group/CADTransformer. SymPoint's comparison table lists it at PQ 68.9, SQ 88.3, RQ 73.3, **>65M parameters** — [SymPoint, arXiv 2401.10556](https://arxiv.org/abs/2401.10556).
- **GAT-CADNet: Graph Attention Network for Panoptic Symbol Spotting in CAD Drawings** — Zheng et al., CVPR 2022. Drawing as graph; vertex features -> semantics, cascaded attention scores -> instances (instance = subgraph detection); relative spatial encoding + cascaded edge encoding. Full model PQ 0.737 (RQ 0.807, SQ 0.914) vs 0.563 for a GCN variant — [arXiv 2201.00625](https://arxiv.org/abs/2201.00625); [CVPR supplemental](https://openaccess.thecvf.com/content/CVPR2022/supplemental/Zheng_GAT-CADNet_Graph_Attention_CVPR_2022_supplemental.pdf).
- **Symbol as Points: Panoptic Symbol Spotting via Point-based Representation (SymPoint)** — Wenlong Liu, Tianyu Yang, Yuhan Wang, Qizhi Yu, Lei Zhang, ICLR 2024. Each primitive becomes one 2D point with a 6-d feature [angle, length, one-hot type in {line, arc, circle, ellipse}]; Attention with Connection Module, Contrastive Connection Learning, KNN interpolation. **PQ 83.3, RQ 91.1, +9.6 PQ over GAT-CADNet, 35M params** — [arXiv 2401.10556](https://arxiv.org/abs/2401.10556); [ICLR 2024 poster](https://iclr.cc/virtual/2024/poster/18367); code nicehuster/SymPoint.
- **SymPoint Revolutionized: Boosting Panoptic Symbol Spotting with Layer Feature Enhancement (SymPoint-V2)** — Wenlong Liu et al. (International Digital Economy Academy; Vanyi Tech), arXiv 2024 (no peer-reviewed venue found). Adds Layer Feature-Enhanced module (pools features per CAD layer ID and fuses back) and Position-Guided Training (extra center queries) for faster convergence. PQ 83.3 -> 90.1 — [arXiv 2407.01928](https://arxiv.org/abs/2407.01928). CADSpotting's table gives SPv2 PQ 90.1 / SQ 96.3 / RQ 93.6 — [CADSpotting, arXiv 2412.07377](https://arxiv.org/abs/2412.07377). **VecFormer's table shows SPv2 at 83.2 PQ without the layer prior vs 90.1 with it** — [VecFormer, arXiv 2505.23395](https://arxiv.org/abs/2505.23395). CADSpotting explicitly criticises SPv2 for depending on layer information that is not always available — [CADSpotting](https://arxiv.org/abs/2412.07377).
- **CADSpotting** (already in review; numbers added): dense equidistant sampling along every primitive (including Bézier curves), Point Transformer V3 backbone + lightweight Transformer decoder; Sliding Window Aggregation (weighted voting + sparse NMS, sparse IoU matrix to save memory). **PQ 87.4 vs SymPoint 83.3** on FloorPlanCAD; LS-CAD = 45 annotated floorplans of ~1,000 m^2 each (vs ~100 m^2 in FloorPlanCAD). No runtime/memory figures found — [arXiv 2412.07377](https://arxiv.org/abs/2412.07377); [ICCVM 2026 version](https://iccvm.org/2026/files/papers/297.pdf). PTv3's own published efficiency (44 ms, 1.2 GB on nuScenes LiDAR) does not transfer to CAD — [PTv3, CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Wu_Point_Transformer_V3_Simpler_Faster_Stronger_CVPR_2024_paper.pdf). A later paper (PolarSym) says SWA "exhibits poor stability and lacks global topological characteristics" — [arXiv 2608.11793](https://arxiv.org/abs/2608.11793).
- **DPSS (ArchCAD-400K baseline)** — Luo et al., NeurIPS 2025. Adaptive fusion of primitive features with image features. Authors claim +3% over second-best on FloorPlanCAD and +10% on ArchCAD-400K — [arXiv 2503.22346](https://arxiv.org/abs/2503.22346); [NeurIPS proceedings](https://proceedings.nips.cc/paper_files/paper/2025/hash/b96ce7d38339874a8704e8895f743284-Abstract-Conference.html). Secondary overview (alphaxiv, not verified against tables): **86.2 PQ on FloorPlanCAD without layer/color priors vs SPv2 83.2; on ArchCAD-400K 70.6 PQ vs SPv2 60.5 and SymPoint 47.6; Stuff-PQ 77.6 vs 52.8** — [alphaxiv overview](https://www.alphaxiv.org/overview/2503.22346v1). The ArchCAD paper states it emphasises the no-prior setting "because the absence of layer and color data more closely reflects real-world conditions" — [arXiv 2503.22346](https://arxiv.org/abs/2503.22346). Its FloorPlanCAD table also reports semantic F1/mAP (e.g. SPv2 89.5 F1 / 60.1 mAP with priors, 87.0 / 57.5 without) — same source; a CADSpotting row of 93.5 F1 / 69.0 mAP appeared in extraction but its setting is unclear.
- **Point or Line? Using Line-based Representation for Panoptic Symbol Spotting in CAD Drawings (VecFormer)** — Xingguang Wei, Haomin Wang, et al., NeurIPS 2025. Every primitive is resampled into line segments (K=2 samples for lines, K=9 for arcs/circles/other types) carrying geometric attributes + primitive-level statistics, fed to a Transformer; training-free "Branch Fusion Refinement" merges instance and semantic branches by confidence. **PQ 91.1 (with prior), 88.4 (without); Stuff-PQ +9.6 and +21.2 over second-best with/without prior** — [arXiv 2505.23395](https://arxiv.org/abs/2505.23395); [NeurIPS 2025 poster](https://neurips.cc/virtual/2025/poster/116604); code WesKwong/VecFormer. Parameter count/latency not found.
- **2026 successors (all arXiv preprints, not peer reviewed as of Oct 2026):**
  - **Text-Aided Multi-Modal Panoptic Symbol Spotting for CAD Floor Plan Drawings (TextCAD)** — arXiv 2607.12678, Jul 2026 (authors not confirmed). Type-Attribute Correlation Encoder for annotation text + Semantic Hierarchy Alignment / Multi-level Semantic Filtering; claims ~2 pp over prior SOTA and a "lightweight" encoder — [arXiv 2607.12678](https://arxiv.org/abs/2607.12678). Successor to the Text-Enhanced PSS paper already in the review.
  - **PolarSym: Polar Geometry-aware Attention for CAD Floorplan Parsing** — arXiv 2608.11793, Aug 2026. Adds direction (SF-RoPE) and distance (RDB) terms as additive attention modulation exploiting building symmetry. **+1.73 PQ, +1.54 RQ, +4.31 mIoU over a reproduced SymPoint-V2** under identical settings — [arXiv 2608.11793](https://arxiv.org/abs/2608.11793); third-party review adds 50-epoch, 2-GPU training and PQ 74.6 vs 58.1 at epoch 20 — [Pith review](https://pith.science/paper/2608.11793). Absolute PQ vs VecFormer not found.
  - **TempFit: Panoptic Symbol Spotting via Template Fitting** — arXiv 2610.17776, Oct 2026. Argues per-primitive classification has no constraint that an instance's primitives be spatially connected (merges distant symbols, fragments one symbol); instead retrieves a canonical template from a library and predicts its pose ("retrieve-and-transform"), via an autoregressive transformer — structural completeness by construction. Reports a new metric PQ_g under which VecFormer scores 66.9 — [arXiv 2610.17776](https://arxiv.org/abs/2610.17776). A ResearchGate snippet describing a DEIM detector + ICP alignment may refer to a baseline/variant (unverified).
  - **Pixel-Wise Symbol Spotting via Progressive Points Location for Parsing CAD Images** — arXiv 2404.10985, 2024: raster-input counterpart (only title/listing seen) — [arXiv 2404.10985](https://arxiv.org/abs/2404.10985).
- **AECV-Bench** (arXiv 2601.04819, Jan 2026) benchmarks VLMs on AEC drawings and finds a performance gradient OCR > spatial reasoning > symbol-centric understanding, i.e. VLMs are weakest at exactly symbol spotting — [arXiv 2601.04819](https://arxiv.org/abs/2601.04819).

### Inferences
- Use the **no-prior** numbers when reasoning about PDFs: CAD layers survive into PDF only as optional content groups when the exporter emits them, and colours are often flattened to black. Realistic ceiling for a vector model on PDF-derived input is therefore ~86-88 PQ (DPSS, VecFormer no-prior), not 90-91.
- The trend is "more geometry per primitive" (point -> dense samples -> line tokens) plus "structural completeness" (TempFit). TempFit's retrieve-and-transform framing is the learned analogue of the training-free block matching recommended in Q3.
- Model sizes (35M to >65M) and dependence on custom CUDA point ops (PTv3 serialization/sparse conv, SymPoint's point ops) make browser deployment of any of these impractical without re-architecting; they are server/GPU models.
- Licence: all are trained on FloorPlanCAD (CC BY-NC 4.0, per the existing review) or ArchCAD-400K; released checkpoints inherit research-only restrictions.

### Gaps
- No inference latency, memory, or FLOPs found for SymPoint-V2, CADSpotting, DPSS, VecFormer, TextCAD, PolarSym or TempFit (full texts were unreachable).
- PolarSym and TempFit absolute PQ on standard FloorPlanCAD PQ not confirmed; TextCAD authors and exact numbers not confirmed.
- No Papers-with-Code-style leaderboard page was reachable; the table is assembled from each paper's self-reported comparisons, which use different reproductions of baselines (e.g. SPv2 = 83.2 vs 90.1 depending on prior).

## Q2. Graph / point representations of PDF/SVG primitives; text and hatching; sensitivity to CAD export quirks

### Takeaway
Three representations dominate: graph (nodes = primitives, edges = proximity/connectivity: GAT-CADNet, VectorFloorSeg, Carrara's PDF-line GNNs), point (SymPoint, CADSpotting) and line tokens (VecFormer). Text is either ignored or fused as a separate modality (TextCAD 2026); hatching is treated as "stuff"; and the main export-quirk sensitivity documented in the literature is dependence on CAD layer/colour metadata, which PDFs usually lose. Direct studies of exploded blocks, split polylines and dashed lines on these models were not found.

### Cited Findings
- SymPoint's fixed 4-type primitive vocabulary (line/arc/circle/ellipse, one-hot) is criticised as restrictive for "more complex and diverse shapes" in real drawings; CADSpotting replaces it with equidistant sampling that also covers Bézier curves — [CADSpotting](https://arxiv.org/abs/2412.07377); [SymPoint](https://arxiv.org/abs/2401.10556).
- VecFormer samples K=2 points for line primitives and K=9 for all other primitive types, turning curves into polyline tokens — [arXiv 2505.23395](https://arxiv.org/abs/2505.23395).
- CADTransformer's "Random Layer" augmentation and SymPoint-V2's Layer Feature-Enhanced module both exploit CAD layer IDs; SPv2 loses ~7 PQ without them (90.1 -> 83.2) — [CADTransformer](https://openaccess.thecvf.com/content/CVPR2022/html/Fan_CADTransformer_Panoptic_Symbol_Spotting_Transformer_for_CAD_Drawings_CVPR_2022_paper.html); [VecFormer table](https://arxiv.org/abs/2505.23395).
- **VectorFloorSeg: Two-Stream Graph Attention Network for Vectorized Roughcast Floorplan Segmentation** — Bingchen Yang, Haiyong Jiang, Hao Pan, Jun Xiao, CVPR 2023. Two GNN streams: line segments (classified as room boundary or not) and the regions they enclose (classified as room types), coupled by modulated graph attention; outperforms image-based methods on mIoU/mAcc and proposes a room-integrity/boundary-regularity metric — [CVPR 2023 poster](https://cvpr.thecvf.com/virtual/2023/poster/21320); [paper PDF](https://openaccess.thecvf.com/content/CVPR2023/papers/Yang_VectorFloorSeg_Two-Stream_Graph_Attention_Network_for_Vectorized_Roughcast_Floorplan_Segmentation_CVPR_2023_paper.pdf); code DrZiji/VecFloorSeg. PolarSym (third party) notes it supports only straight segments (curves need polygonal approximation) and misclassifies narrow regions such as corridors — [arXiv 2608.11793](https://arxiv.org/abs/2608.11793).
- **Carrara et al., line detection/classification in PDF technical drawings** (TUM, I3CE 2024): processes vector PDFs into a graph and classifies each line into walls (external contours), openings, measurement elements, symbols, other; training labels made by hand in Inkscape as SVG layers — [mediaTUM PDF](https://mediatum.ub.tum.de/doc/1748705/vjffmc66e8g1p1nfeet4k1i3f.2024_Carrara_I3CE.pdf). Journal follow-up **VectorGraphNET: Graph Attention Networks for Accurate Segmentation of Complex Technical Drawings**, ASCE J. Computing in Civil Engineering, 2025: each vector primitive a node, multilevel labels ("annotation" vs "architecture"), argues per-line granularity matters where dimension lines cross arrows — [ASCE DOI 10.1061/JCCEE5.CPENG-6508](https://ascelibrary.org/doi/10.1061/JCCEE5.CPENG-6508). This is the closest published work to "GNN on pdf.js-extracted paths".
- Carrara et al., **Content-based Classification of Construction Drawings** (EG-ICE 2025): building the graph from a vector plan is "notably more time-consuming than rasterization" — [mediaTUM PDF](https://mediatum.ub.tum.de/doc/1781828/sdbdwmsyswh5qjjiqmby19z8r.eg-ice2025_Carrara.pdf).
- GCN on a connectivity graph of lines and arcs classifying 9 entity types (dimension, center, hidden lines, etc.) in engineering drawings — [Component segmentation of engineering drawings using GCNs (ResearchGate)](https://www.researchgate.net/publication/370431419_Component_segmentation_of_engineering_drawings_using_Graph_Convolutional_Networks).
- **Text handling**: TextCAD (2026) models annotation text as a typed modality fused with geometry and claims ~2 pp PQ gain — [arXiv 2607.12678](https://arxiv.org/abs/2607.12678); its predecessor (Liu et al. 2025) is already in the review.
- **Hatching / "stuff"**: VecFormer's main reported gain is on Stuff categories (walls, hatch-like regions), +9.6/+21.2 Stuff-PQ; DPSS reports Stuff-PQ 77.6 vs 52.8 for SPv2 on ArchCAD-400K (secondary source) — [VecFormer](https://arxiv.org/abs/2505.23395); [alphaxiv on DPSS](https://www.alphaxiv.org/overview/2503.22346v1).
- **Dashed lines in PDFs**: practitioners report that PDF import yields dashes as many short polyline pieces whose tiny end pieces point at odd angles, breaking downstream operations; AutoCAD's "infer linetypes from collinear dashes" struggles on wavy lines — [Autodesk Community thread](https://forums.autodesk.com/t5/autocad-lt-forum/import-pdf-function-not-recognizing-hidden-lines/td-p/9142018).
- **Fragment merging recipe**: Deep Vectorization's post-process builds a graph of primitives that are close and nearly collinear, replaces each component with one least-squares line, trims dangling ends and snaps intersecting endpoints — [Egiazarian et al., arXiv 2003.05471](https://arxiv.org/abs/2003.05471). A 2026 floorplan-vectorization paper snaps endpoints to junctions, simplifies with Douglas-Peucker, and snaps to dominant axes with tolerance tied to wall thickness — [arXiv 2608.25608, "When Should a Network Emit Geometry, and When Should It Detect It?"](https://arxiv.org/abs/2608.25608).
- pdf.js batches consecutive path operators (m, l, c, re, ...) into a single `constructPath` operator in the operator list (since 2014) — [pdf.js commit log](https://lists.alioth.debian.org/pipermail/pkg-javascript-commits/2014-June/008235.html); [re folded into constructPath](https://lists.alioth.debian.org/pipermail/pkg-javascript-commits/2014-July/010619.html).

### Inferences
- PDF paths are a strict subset of what these models consume: lines and cubic Béziers only (arcs/circles arrive as 1-4 Bézier segments), no layer IDs unless OCGs exist, no block references. A PDF-to-model adapter therefore needs (a) Bézier-to-arc recovery (fit circle to control points) to restore SymPoint-style type features, (b) collinear-dash merging, (c) optional OCG name -> layer ID. The no-prior numbers in Q1 are the relevant ones.
- Line-token (VecFormer) and dense-sample (CADSpotting) representations should be more tolerant of polylines split into segments than SymPoint's one-point-per-primitive, because fragmenting a line changes the token count but not the sampled geometry; this is inference, not tested in any paper found.
- Text in a CAD-exported PDF is often real text (getTextContent) but sometimes stroked glyph outlines (SHX fonts exported as vectors). Those would pollute any geometry-only primitive graph; a small "glyph-like cluster" filter (many short strokes in a tight bbox) is needed before graph building.

### Gaps
- No paper found that measures FloorPlanCAD-model robustness to exploded blocks, split polylines, dashed lines, or SHX-text-as-geometry.
- How FloorPlanCAD/SymPoint preprocessing treats text and hatch entities in the SVGs (dropped vs labelled) was not confirmed.
- Carrara/VectorGraphNET accuracy figures and the PDF parsing library used were not retrievable.
- pdfjs-dist 5.x changed the internal `constructPath` argument layout (my recollection, not verified in this sweep); the exact v5 operator-list format must be checked against `src/core/evaluator.js` before implementation.

## Q3. Exploiting repetition without learning: block/instance detection from identical vector path signatures, geometric hashing

### Takeaway
There is a mature, pre-deep-learning literature on indexing and hashing vector primitives for query-by-example symbol spotting (graph-path hashing, region hashing, relational indexing, symbol-library discovery by clustering repeated patterns), and the 2026 TempFit paper re-legitimises the "retrieve a template and fit its pose" view. No paper or open tool was found that specifically recovers CAD blocks from exploded PDF geometry by exact path signatures, which suggests it is folklore/commercial practice (Bluebeam "Auto Count" is described by resellers as relying on consistent CAD blocks) rather than published research.

### Cited Findings
- **Building a Symbol Library from Technical Drawings by Identifying Repeating Patterns** — Nibal Nayef, Thomas M. Breuel, GREC 2011 / Graphics Recognition: New Trends and Challenges, LNCS 2013. Finds candidate patterns, clusters similar ones (rotation/scale-tolerant geometric matching), keeps one representative per cluster as an indexable symbol library; poster reports 98.8% recall / 97.31% precision on grouping (13,780 patterns, 30 clusters) and 99%/98% retrieval on 7 queries — [Springer DOI 10.1007/978-3-642-36824-0_7](https://link.springer.com/chapter/10.1007/978-3-642-36824-0_7); [ICVSS 2011 poster](https://icvss.dmi.unict.it/icvss2011/Poster/Nibal-poster.pdf). This is the closest published analogue of unsupervised "find every repeated block on the sheet".
- **Symbol Spotting in Line Drawings Through Graph Paths Hashing** — Dutta, Lladós, Pal (ICDAR 2011): graph of vectorization critical points, acyclic paths with geometric attributes, locality-sensitive hashing + spatial voting, robust to noise/distortion — [ResearchGate](https://www.researchgate.net/publication/224265575_Symbol_Spotting_in_Line_Drawings_Through_Graph_Paths_Hashing); journal version **A symbol spotting approach in graphical documents by hashing serialized graphs**, Pattern Recognition 2013 — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0031320312004359).
- **A Region-Based Hashing Approach for Symbol Spotting in Technical Documents** — Rusiñol, Lladós et al., GREC 2008: describes symbols by closed contours/regions, motivated by the limitation that classical geometric hashing works well only when model and test have the same number of segments — [GREC08 PDF](https://marcalr.github.io/pdfs/GREC08.pdf). (Relational indexing of vectorial primitives, PRL 2010, is already in the review.)
- Geometric hashing basics: offline invariant tables from 2- or 3-point bases; a 3-point basis also catches mirrored instances — [Wikipedia: Geometric hashing](https://en.wikipedia.org/wiki/Geometric_hashing).
- **TempFit** (arXiv 2610.17776, 2026) frames symbol spotting as retrieving a canonical template from a library and aligning it, mirroring the CAD "retrieve-and-transform" workflow — [arXiv 2610.17776](https://arxiv.org/abs/2610.17776).
- **Vendor/practitioner claims (not peer reviewed):** Bluebeam VisualSearch is a box-one-example pattern matcher with sensitivity, rotation, scale and colour options; resellers advise combining it with Auto Count "when drawings use consistent CAD blocks" and falling back to VisualSearch for scans — [NOVEDGE tip](https://novedge.com/blogs/design-news/bluebeam-tip-detect-and-count-repeated-symbols-with-visualsearch-and-ocr); [NOVEDGE tip 2](https://novedge.com/blogs/design-news/bluebeam-tip-automate-symbol-counts-with-visualsearch-and-a-saved-count-tool). A practitioner blog states clean vector PDFs count far better than scans and that a symbol drawn slightly differently is missed — [sagnikbhattacharya.com](https://sagnikbhattacharya.com/blog/electricians-ai-count-fittings-drawings).

### Inferences
- For CAD-exported vector PDFs, a training-free "click one symbol -> find all" tier is very likely to beat the current raster matcher on precision: (1) collect the paths inside the clicked bbox, (2) canonicalise (translate to centroid, normalise by bbox diagonal, rotate to principal axis or try the 4/8 orthogonal rotations plus mirror), (3) hash a quantised, order-independent signature (sorted multiset of segment lengths/angles/curve-type), (4) look up candidates anywhere on the page via a spatial index of path groups, (5) verify with a symmetric Chamfer/Hausdorff distance on sampled points. Exact matches are cheap because CAD exporters typically emit every block instance with identical relative geometry; tolerant matching (graph-path or region hashing per Dutta/Rusiñol) covers split segments.
- Repetition also gives free training labels: clusters found this way are exactly the "blocks are free ground truth" signal the review notes for ArchCAD-400K, but derivable from any customer PDF client-side.
- Some CAD exporters emit blocks as PDF Form XObjects; if so, `paintFormXObjectBegin` boundaries in the operator list give instance grouping for free. This is an unverified hypothesis worth a quick check on sample PDFs.

### Gaps
- No paper or open-source tool found that explicitly reconstructs exploded CAD blocks from PDF path signatures, nor any benchmark of exact-signature counting on real exported PDFs.
- Bluebeam's own documentation of how Auto Count / VisualSearch treat vector geometry was not reached; reseller statements only.

## Q4. Extracting walls, doors (arc + line) and rooms from vector PDFs; raster-to-vector as fallback

### Takeaway
Vector-first wall/door/room extraction is mostly rule-based and old (wall adjacency graphs, arc-based door hypotheses, planar-face room recovery), with VectorFloorSeg (CVPR 2023) as the main learned vector method for rooms. For raster fallback, 2026 brought Raster2Seq (SIGGRAPH 2026, autoregressive polygon sequences, RoomF1 88.7 on CubiCasa5K per model card) and VLM-assisted pipelines (SALI-FP, SIM 2.0), all server-class.

### Cited Findings
- Classic arc-based door detection: Hough-transform + vectorization line extraction, walls grouped from lines, door hypotheses from extracted arcs, feeding room segmentation — Macé, Locteau, Valveny, Tabbone, **A System to Detect Rooms in Architectural Floor Plan Images**, DAS 2010 — [ACM DOI 10.1145/1815330.1815352](https://dx.doi.org/10.1145/1815330.1815352); [CEUR summary](https://ceur-ws.org/Vol-3581/194_WiP.pdf).
- Structural recognition with walls as graph vertices and connections as edges, A* search to find doors/windows — de las Heras, Sánchez, Lladós et al. (CVC) — [HSL2013 PDF](https://refbase.cvc.uab.es/files/HSL2013.pdf).
- Born-digital CAD: a wall adjacency graph detects walls from planar segments and locates joints and openings — **Semiautomatic detection of floor topology from CAD architectural drawings** (Domínguez, García, Feito, Computer-Aided Design 2012) — [ResearchGate](https://www.researchgate.net/publication/256688203_Semiautomatic_detection_of_floor_topology_from_CAD_architectural_drawings). A rule-based pipeline that standardises plans to lines and arcs then filters lines to rooms, extracting doors/windows last — [arXiv 1710.01802](https://arxiv.org/abs/1710.01802) (title/authors not confirmed in this sweep).
- Door detection on CVC-FP is noted as problematic because doors are drawn with thin lines — [CEUR WiP paper](https://ceur-ws.org/Vol-3581/194_WiP.pdf).
- **VectorFloorSeg** (CVPR 2023): room segmentation directly on vector line segments + enclosed regions, beats image methods — [CVPR 2023](https://cvpr.thecvf.com/virtual/2023/poster/21320). **Parsing Line Segments of Floor Plan Images Using Graph Neural Networks** (arXiv 2303.03851, 2023) is a GNN line-segment parser for floor plans (title only seen) — [arXiv 2303.03851](https://arxiv.org/abs/2303.03851).
- **Training-Free Agentic Computer Vision for Structural Component Detection in 2D Structural Framing Plans** (arXiv 2608.17237, 2026): training-free agentic detection on structural plans (title/listing only) — [arXiv 2608.17237](https://arxiv.org/abs/2608.17237).
- **Raster2Seq: Polygon Sequence Generation for Floorplan Reconstruction** — Hao Phung, Hadar Averbuch-Elor (Cornell), SIGGRAPH 2026. Autoregressive next-corner decoder with learnable image-anchored anchors; SOTA claims on Structured3D, CubiCasa5K, Raster2Graph and generalisation to WAFFLE; avoids RoomFormer's short-cut triangular polygons — [arXiv 2602.09016](https://arxiv.org/abs/2602.09016). Model card: RoomF1 88.7 CubiCasa5K, 99.6 Structured3D-B, 97.0 Raster2Graph (author-reported) — [HF haopt/Raster2Seq](https://huggingface.co/haopt/Raster2Seq).
- **Evidence-gated multimodal parsing and vectorization of architectural floor plans (SALI-FP)** — arXiv 2609.25615, 2026: model proposes semantic edits that must pass local evidence gates; structured outputs for 11,534 heterogeneous plans; ran the Raster2Seq checkpoint on CPU as a baseline — [arXiv 2609.25615](https://arxiv.org/abs/2609.25615). Mentions SIM 2.0 (SIGSPATIAL '26), a VLM-based floor-plan vectorization system working across styles without retraining (same source).
- **Vectorizing Building Blueprints** — Song et al., ACCV 2022: off-the-shelf segmentation + refinement + heuristic simplification for high-res blueprints — [CVF](https://openaccess.thecvf.com/content/ACCV2022/html/Song_Vectorizing_Building_Blueprints_ACCV_2022_paper.html).
- Commercial state of practice (already in review): closing openings by replacing doors/windows with solid lines (Kreo).

### Inferences
- On a vector PDF, doors are unusually easy: a quarter-circle swing is emitted as one cubic Bézier (or a short run) whose control points fit a circle of radius r, adjacent to a straight leaf of length ~r sharing the arc's centre/endpoint. Detecting (arc of ~90 degrees, radius 600-1200 mm at sheet scale) + (line of equal length from the centre) is a tens-of-lines heuristic, and its chord gives the exact opening to close for room fill — the vector version of the DeepFloorplan "doors as boundary" fix already planned in patch 2 Tier B.
- Rooms then become faces of the planar arrangement of wall segments plus door chords (polygonize after noding and snapping), yielding exact areas with no raster flood-fill leak; VectorFloorSeg shows learning can classify those faces, but face extraction itself is deterministic.
- Wall recognition on vector PDFs: parallel-line pairs at a consistent offset (wall thickness), often with heavier stroke widths; stroke width and dash pattern are available in the operator list (`setLineWidth`, `setDash`), a strong free feature that raster pipelines discard.
- Raster fallback (scans): Raster2Seq/HEAT-class models are server-side; for the browser, the existing raster flood fill + patch-2 closing remains the fallback.

### Gaps
- No 2023-2026 peer-reviewed paper found that parses walls/doors/rooms specifically from PDF vector content streams (as opposed to DWG/DXF/SVG or rasters); Carrara/VectorGraphNET is the closest (line classes including walls and openings).
- No quantitative accuracy found for arc-based door heuristics on modern CAD-exported PDFs.

## Q5. Practical recommendations for pdf2takeoff: in-browser (pdf.js operator lists) vs server

### Takeaway
The highest-value, lowest-risk move is a deterministic vector tier, not a model: extract paths from `page.getOperatorList()` in the browser, then do exact/tolerant repeated-geometry matching for counts, arc+line door detection, and planar-face room polygons. Learned vector spotters (SymPoint/VecFormer/DPSS-class) are GPU models with research-only training data and belong on an optional server, behind the same interfaces; they would mainly add semantic class names, not counting accuracy, on clean CAD PDFs.

### Cited Findings
- pdf.js exposes path geometry through the operator list, grouping consecutive path-construction ops into `constructPath` — [pdf.js commit log](https://lists.alioth.debian.org/pipermail/pkg-javascript-commits/2014-June/008235.html); spec mapping of m/l/c/v/y/re/h — [pdfjs-docs](https://github.com/MeiKatz/pdfjs-docs). pdf2takeoff already depends on `pdfjs-dist ^5.4.149` but does not use the operator list (repo grep, `package.json`, `src/`).
- Building graphs from vector plans is slower than rasterising (Carrara EG-ICE 2025) — [mediaTUM](https://mediatum.ub.tum.de/doc/1781828/sdbdwmsyswh5qjjiqmby19z8r.eg-ice2025_Carrara.pdf).
- Learned SOTA models: SymPoint 35M params, CADTransformer >65M — [SymPoint](https://arxiv.org/abs/2401.10556); CADSpotting relies on PTv3 and a sliding window with sparse NMS to fit large sheets in memory — [CADSpotting](https://arxiv.org/abs/2412.07377); no-prior PQ ceiling ~86-88 — [VecFormer](https://arxiv.org/abs/2505.23395), [ArchCAD-400K](https://arxiv.org/abs/2503.22346).
- Vendors steer clean-vector-PDF users toward block-consistent auto counting and use visual search for scans (reseller claim) — [NOVEDGE](https://novedge.com/blogs/design-news/bluebeam-tip-detect-and-count-repeated-symbols-with-visualsearch-and-ocr).
- VLMs remain weakest at symbol-centric drawing understanding — [AECV-Bench, arXiv 2601.04819](https://arxiv.org/abs/2601.04819).

### Inferences (recommended plan, ordered by value/effort)
1. **Vector extraction module (browser, no model).** `page.getOperatorList()` -> walk ops tracking CTM (`save/restore/transform`), stroke/fill, `setLineWidth`, `setDash`, colour, Form XObject begin/end, and `constructPath` contents -> a flat list of primitives in PDF-point space (line, cubic, rect; fitted arcs). Cache per page like raster caches. Gate on "is this page vector?" (path count > N and few/no image ops). Expected cost: one pass per page, milliseconds to low seconds on dense A0 sheets (inference; no benchmark found).
2. **Scan tier 0: exact/tolerant vector match (browser).** Click -> paths in bbox -> canonical signature -> hash lookup over all path groups -> Chamfer verification -> counts with 100%-reproducible results on CAD exports; fall back to the existing raster tiers on scanned pages. Literature basis: Nayef & Breuel 2013, Dutta et al. 2011/2013, Rusiñol 2008, TempFit 2026. This directly targets the "symbols touching lines" blind spot of the raster tier, since vector paths are separable even when they overlap ink.
3. **Vector room fill (browser).** Snap/merge collinear fragments (Deep Vectorization merge rule), filter by stroke width to wall candidates, add door chords from arc+line detection, node the arrangement, and return the face containing the click. Exact area, no dilation inflation; falls back to `dynamicfill.ts` raster path on non-vector pages.
4. **Text-proximity features for free.** `getTextContent()` positions let the vector matcher disambiguate lookalikes by nearby tags (the idea TextCAD/Liu 2025 learn), without any model.
5. **Server (optional, later).** A VecFormer- or DPSS-class model behind the MCP/headless engine for whole-sheet semantic spotting ("count all sinks") when the user has not clicked an exemplar; needs GPU, a PDF-to-primitive adapter (Bézier-to-arc, dash merging), and licence-clean training data (FloorPlanCAD/ArchCAD checkpoints are research-only). Not worth it before tiers 1-3, because on clean CAD PDFs the deterministic tiers should already count near-perfectly within one symbol type.
6. **Raster-to-vector fallback for scans**: keep server-side (Raster2Seq/HEAT class); in-browser stays the current raster pipeline.

### Gaps
- No published measurement of pdf.js operator-list extraction speed or memory on large construction sheets; needs an in-repo benchmark.
- Not verified whether common CAD exporters (AutoCAD, Revit, MicroStation, ArchiCAD) emit blocks as Form XObjects, keep OCG layers, or write dashes as `setDash` vs pre-split segments; this determines how much of tier 2/3 is exact vs tolerant and should be checked on the repo's sample PDFs.
