## Q1. How well do current VLMs understand construction/technical drawings, and which benchmarks measure it (2024-2026)?

### Takeaway
Every 2024-2026 drawing benchmark found shows the same split. Frontier VLMs read text well (OCR around 0.95 on AECV-Bench). They fail at symbol counting (around 0.40-0.55 accuracy; the best model gets 54% exact match on door/window/room counts), at mapping a scale to a number (MeasureBench best is around 30%), and at reasoning across a whole large sheet (LED-BENCH best is 52.65%). Giving agents images does not close the gap: AEC-Bench found that heavy rasterization did not improve visually grounded tasks. The general counting and difference benchmarks (CountQA, HoloCount, DiffSpot, VDiff-Bench) show the same failure modes outside AEC.

### Cited Findings

**AEC drawing benchmarks (new since the repo review)**
- **AECV-Bench: Benchmarking Multimodal Models on Architectural and Engineering Drawings Understanding**. Kondratenko, Hsain, Birhane, Maciocci (AECFoundry), arXiv 2601.04819, Jan 2026 **[preprint]**. It has two parts: (1) object counting on 120 floor plans (doors, windows, bedrooms, toilets) and (2) 192 drawing-grounded QA pairs covering OCR, spatial reasoning, instance counting and comparative reasoning. — [arXiv](https://arxiv.org/abs/2601.04819); [GitHub](https://github.com/AECFoundry/AECV-Bench)
  - Models evaluated: Claude Opus 4.5, Gemini 3 Pro Preview, GPT-5.2, Grok 4.1 Fast, Mistral Large 2512, Qwen3-VL 8B, GLM-4.6V, Nemotron Nano 12B V2 VL, Nova 2 Lite, Command A Vision. Metrics: exact-match accuracy, MAPE for counts, per-category recall, and a GPT-4o LLM judge for QA. — [GitHub README](https://github.com/AECFoundry/AECV-Bench)
  - Text-centric tasks such as OCR reach about 0.95 accuracy. Symbol-centric counting of doors and windows lags at about 0.40-0.55, with large proportional errors. Models read room labels well but struggle to recognise doors and windows. — [arXiv 2601.04819](https://arxiv.org/pdf/2601.04819) (via search extraction); [EmergentMind summary](https://www.emergentmind.com/topics/aecv-bench)
  - Project site: the top counting model is listed as "Gemini 3.5 Flash" at 54.3% mean exact match and 15.3% MAPE. The best open-source model reaches 47%, and counting "remains unreliable". The model name differs from the paper's model list, presumably a later leaderboard update. Unverified against the paper. — [aecv-bench.com](https://aecv-bench.com/)
- **AEC-Bench: A Multimodal Benchmark for Agentic Systems in Architecture, Engineering, and Construction**. Mankodiya, Gallik, Galanos, Mulyar (Nomic AI), arXiv 2603.29199, Mar 2026 **[preprint; benchmark from a tooling vendor]**. It has 196 task instances across 9 task types at three scopes. Intra-sheet: detail technical review, detail title accuracy, note-callout accuracy. Intra-drawing: cross-ref resolution, cross-ref tracing, sheet-index consistency. Intra-project: drawing navigation, spec-drawing sync, submittal review. It runs in Docker through the Harbor framework, with Claude Code and Codex CLI harnesses. Apache-2.0. — [GitHub](https://github.com/nomic-ai/aec-bench); [arXiv](https://arxiv.org/abs/2603.29199)
  - The study compares Codex (GPT-5.2, GPT-5.4) and Claude Code (Opus 4.6, Sonnet 4.6) in a base harness (H) and in a harness plus Nomic Parse and Embeddings (H+N). The parse tools give average gains of +32.2% on Detail-Technical-Review, +20.8% on Spec-Drawing-Sync and +18.75% on Drawing-Navigation. The paper says parsing helps text-heavy retrieval but "is less effective for tasks requiring fine-grained visual grounding". — [arXiv 2603.29199](https://arxiv.org/pdf/2603.29199) (via search extraction)
  - Tool-use telemetry: 77% of agent trajectories used `pdftotext` as the main extraction method. Codex agents rasterized with `pdftoppm` in 96% of runs and Claude agents in 32%, but the extra image rendering "does not lead to better performance on visually grounded tasks". Access to images alone is not enough without spatial interpretation. — [Nomic blog](https://www.nomic.ai/news/aec-bench-a-multimodal-benchmark-for-agentic-systems-in-architecture-engineering-and-construction); [arXiv HTML](https://arxiv.org/html/2603.29199v1) (via search extraction)
  - Nomic's own agent reports mean reward of 70.6 intra-sheet (8.1 points above the next configuration), 88.3 intra-drawing and 62.0 intra-project. This is self-reported by the vendor. — [Nomic blog](https://www.nomic.ai/news/aec-bench-a-multimodal-benchmark-for-agentic-systems-in-architecture-engineering-and-construction)
- **LED-BENCH: A Benchmark for Large-format Engineering Drawing Understanding**. arXiv 2610.19571, 14 Oct 2026 **[preprint]**. It covers large-format mechanical, architectural and transportation drawings, with questions written and verified by engineering-trained annotators. Of 11 MLLMs (8 proprietary, 3 open), the best was "GPT-5.6 Sol" at 52.65% average accuracy. Every model degraded on questions that need evidence from a broader region of the sheet. — [arXiv](https://arxiv.org/abs/2610.19571)
- **MMArch: Benchmarking Multimodal Reasoning Grounded in Architectural Evidence**. arXiv 2608.09281, 2026 **[preprint]**. It has 1,212 short-answer items built from figures in architecture and civil-engineering papers. Of 18 models, the best open-weight model scored about 30% and the best proprietary model about 52%, against about 95% for human experts. Errors come mostly from applying principles and combining evidence across figures, not from locating evidence. — [arXiv](https://arxiv.org/abs/2608.09281v1)
- **MechVQA: Benchmarking and Enhancing Multimodal LLMs on Comprehensive Mechanical Drawing Understanding**. arXiv 2605.30794, 2026 **[preprint]**. The mechanical-drawing sibling, built from educational and professional materials. Only the existence and scope were verified. — [arXiv](https://arxiv.org/abs/2605.30794)
- **Benchmarking Deep Learning Approaches for AEC Engineering Drawing Layout Detection and Information Extraction**. Huang et al. (Buro Happold / Birmingham City Univ.), arXiv 2607.18997, prepared for EC3 2026 **[preprint / conference]**. 551 facade engineering drawings, 9 layout categories (ADIRO ontology). RF-DETR(m) scored mAP50 0.949; Qwen3-VL-8B had the best extraction F1 at 0.911. Models pre-trained on general document layouts suffer "domain interference". — [arXiv](https://arxiv.org/abs/2607.18997)
- **CEQuest: Benchmarking Large Language Models for Construction Estimation**. Wu, Wang, Liu, arXiv 2508.16081, 2025 **[preprint]**. QA on drawing interpretation and estimation with Gemma 3, Phi-4, LLaVA, Llama 3.3 and GPT-4.1. Conclusion: "considerable room for improvement". Per-model numbers were not retrieved. — [arXiv](https://arxiv.org/abs/2508.16081); [GitHub](https://github.com/mlsysx/CEQuest)
- **DesignQA: A Multimodal Benchmark for Evaluating LLMs' Understanding of Engineering Documentation**. Doris, Grandi, Tomich, Alam, Ataei, Cheong, Ahmed (MIT/Autodesk Research), J. Computing and Information Science in Engineering, Dec 2024 (IDETC-CIE 2024) **[peer-reviewed]**. About 1,451 questions from Formula SAE rules plus CAD images and drawings. GPT-4o, GPT-4, Claude-Opus, Gemini-1.0 and LLaVA-1.5 struggled to extract rules reliably, to identify components in CAD images and to analyse engineering drawings. Earlier-generation context. — [arXiv 2404.07917](https://arxiv.org/abs/2404.07917); [MIT DSpace](https://dspace.mit.edu/handle/1721.1/169000)

**General counting / measuring / difference benchmarks that transfer to takeoff**
- **Do Vision-Language Models Measure Up? Benchmarking Visual Measurement Reading with MeasureBench**. Lin et al. (FlagEval/BAAI), CVPR 2026 **[peer-reviewed]**. 26 instrument types; 1,272 real images plus a synthetic set; 17 VLMs. Best accuracy is about 30.2% on real images and 26.3% on synthetic (the dataset card says 30.3/26.1). Unit recognition is above 90%, but models "falter on mapping scales to numeric values": they read the digits yet misplace the pointer or alignment positions, which produces large numeric errors. GRPO fine-tuning of Qwen2.5-VL-7B on synthetic data helped, less so on real images. This is the closest public analogue to "read a scale bar or dimension and convert it". — [CVPR 2026 paper](https://openaccess.thecvf.com/content/CVPR2026/papers/Lin_Do_Vision-Language_Models_Measure_Up_Benchmarking_Visual_Measurement_Reading_with_CVPR_2026_paper.pdf); [project page](https://flageval-baai.github.io/MeasureBenchPage/)
- **CountQA: How Well Do MLLMs Count in the Wild?** Tamarapalli, Grover, Pande, Yerramilli, arXiv 2508.06585, 2025 **[preprint]**. More than 1,500 QA pairs on dense, cluttered and occluded scenes, 15 models. The best (Gemini 2.5 Pro) scores 42.9% exact match; OpenAI and Anthropic models all score below 35%. Even for 1-5 objects the best model gets only 60.3%, and accuracy falls as counts rise. — [arXiv](https://arxiv.org/abs/2508.06585)
- **HoloCount: A Holistic Visual Counting Benchmark for MLLMs**. arXiv 2607.06420, 2026 **[preprint]**. Qwen3.5-27B scores 20.0% exact on the high-density subset against more than 80% on the other subsets, so density is the failure axis. Electrical and RCP sheets are exactly this case. — [arXiv](https://arxiv.org/html/2607.06420v1) (via search extraction)
- **DiffSpot: Can VLMs Spot Fine-Grained Visual Differences in Web Interfaces?** arXiv 2605.29615, 2026 **[preprint]**. 4,400 image pairs including 500 no-diff controls; 13 frontier VLMs zero-shot. The best model finds 40.7% of true changes, and hard-tier recall is below 23% for every model. Pixel-change magnitude does not predict recall. — [arXiv](https://arxiv.org/html/2605.29615)
- **VDiff-Bench: A Challenging Benchmark for Fine-Grained Image Difference Identification**. arXiv 2609.06245, 2026 **[preprint]**. 1,756 four-option questions across 10 change categories and 11 MLLMs. On low-level questions, models choose "no difference" up to 80.9% of the time, a systematic bias toward missing changes. — [Papers with Code entry](https://paperswithcode.co/paper/2609.06245)

### Inferences
- Frontier VLMs fail most on counting (AECV-Bench, CountQA, HoloCount), scale-to-number conversion (MeasureBench) and whole-sheet integration (LED-BENCH). These are pdf2takeoff's three core numeric operations (scan/count, set_scale/measure, sheet-wide takeoff). This is stronger and more recent evidence for the repo's "numbers from deterministic tools" rule than the 2026 VQA papers already cited.
- AEC-Bench's telemetry (77% `pdftotext`; rasterizing doesn't help) indicates that agents already use a text layer as their main channel when given shell access. A first-class, coordinate-bearing `read_text` MCP tool (the shipped Patch 4) matches what agents do on their own and gives them positions as well.
- The "no difference" bias (VDiff-Bench) and roughly 41% change recall (DiffSpot) mean an agent should never be asked to "look at both revisions and say what changed". It should be given the output of `compare_revisions`.

### Gaps
- Per-model AECV-Bench counting tables (per class, per model) and AEC-Bench Table 2 cells (H vs H+N by model) were not retrievable. The PDFs and repo `results/` folders hold them.
- No benchmark found tests **length/area measurement from a scaled drawing** by a VLM (as opposed to instrument reading or counting). That is an open niche pdf2takeoff could fill (see Q5).
- No public scores found for frontier models on dense electrical/MEP symbol counting specifically. AECV-Bench covers architectural floor plans only.

## Q2. LLM/VLM agents for takeoff, cost estimation, BIM/IFC querying and drawing review: tool-use architectures and evidence that tool grounding improves numbers

### Takeaway
The strongest 2026 evidence is Handoff-H1, a vendor-authored preprint. Its orchestrated pipeline (CV models, then tool-using vision agents, plus a project knowledge base) scores 81.6 composite on real blueprint takeoffs, while seven frontier models run as generic tool-using agents on the same PDFs score 34.7-61.4. That suggests domain-specific tools and orchestration matter more than the base model. On the BIM side, TUM's agentic code-execution over IFC beats non-agentic baselines by 29.5-48.5 points. The data representation (IFC/SQL/JSON/graph) matters little. The real bottleneck is faithful value extraction and unit handling.

### Cited Findings
- **Handoff-H1: An Orchestrated Vision-Agent System for Material Quantity Takeoff from Construction Blueprints**. Handoff (YC company), arXiv 2608.15032, Aug 2026 **[vendor-authored preprint: the company built both the system and the benchmark]**. Architecture has three layers: (1) computer-vision models extract drawing elements, (2) tool-using vision agents run image operations and counting/detection tools, (3) a persistent project knowledge base supplies construction conventions. — [arXiv](https://arxiv.org/abs/2608.15032)
  - Benchmark ("TakeoffBench-V1"): 10 real residential blueprint sets with consensus-validated expert takeoffs (2,009 verified line items). Each line item is scored on **coverage** (was the material found) and **P@.25** (quantity within ±25%), combined into a composite by a per-trade judge. Launch materials say "15 sets", which conflicts with the paper's 10. — [arXiv PDF](https://arxiv.org/pdf/2608.15032) (via search extraction); [YC launch](https://www.ycombinator.com/launches/RdZ-handoff-h1-a-takeoff-model-that-outperforms-human-estimators)
  - Results: H1 scores 81.6 composite (86.1 coverage, 78.8 P@.25). Independent professional estimators score 77.6 composite (65.5 coverage, **87.9 P@.25**). Frontier/open models as tool-using agents from raw PDFs: claude-fable-5 61.4 (77.3/52.8), gpt-5.6 58.6, claude-opus-4-8 54.6, Kimi-K2.6 54.5, claude-sonnet-4-6 53.9, GLM-5.2 41.6, DeepSeek-V4-Pro 34.7. Table values come from search extraction of the parsed table, so verify them. **Humans still beat H1 on quantity precision (87.9 vs 78.8)**; H1's lead comes from coverage. — [arXiv PDF](https://arxiv.org/pdf/2608.15032)
  - No per-layer ablation numbers were retrieved. — (gap)
- **AEC-Bench** (see Q1) **[preprint]**: adding a structured-parse tool (Nomic Parse) to Claude Code and Codex harnesses raised retrieval-heavy drawing tasks by +18.75 to +32.2% on average, but not visually grounded ones. — [arXiv 2603.29199](https://arxiv.org/pdf/2603.29199)
- **Natural Language Information Retrieval from BIM Models: An LLM-Based Multi-Agent System Approach**. Hellin et al. (TUM), EC3 2025 **[peer-reviewed conference]**. The agent calls Python tool functions that operate directly on IFC: gross floor area, glazing area, property-set quantity extraction. The group's earlier ReAct agent reached about 80% on 99 queries working on raw IFC. — [EC3 2025](https://ec-3.org/publication/ec32025_265/); [TUM PDF](https://mediatum.ub.tum.de/doc/1781947/66amsnnaqbygipuftj8b88oqv.2025_HELLIN_EC3.pdf)
- **ifc-bench v2 / adaptive exploration**. Hellin, Jang, Fuchs, Nousias, Borrmann (TUM), 2026 (journal; exact venue not confirmed) **[status unverified]**. 1,027 tasks over 37 IFC models from 21 projects. The agent writes and runs code to discover model structure at runtime. Agentic search beats the non-agentic baseline by 29.5-48.5 points, with 76.3% best accuracy, and the reported finding is that "model quality mattered more than LLM backbone". Reported via an author-group LinkedIn post, so secondhand. — [LinkedIn post](https://de.linkedin.com/in/amirojalvo); [chatpaper listing](https://chatpaper.com/chatpaper/paper/275152)
- **Querying BIM Models with LLM Agents: A Comparison of Data Representations** (Du et al., with the TUM group; ECPPM per secondhand report) **[Zenodo record; status unverified]**. Four representation/tool pairings (IFC STEP + IfcOpenShell, JSON, SQL, property graph + Cypher) on 507 IFC-Bench questions, all landing at about 75-79% accuracy. IfcOpenShell needed the fewest tool calls. The bottleneck is "faithfulness in value extraction and unit handling", not format. — [Zenodo](https://zenodo.org/records/22679659)
- **IFCMemoryBench: Evaluating Long-Term Memory of LLM-Based Agents in BIM Information Retrieval**. Du, Vosseler, Mazza, Borrmann, arXiv 2607.26072, 2026 **[preprint]**. 143 multi-session tasks; the best memory system reaches 32.4% under realistic ingestion. — [arXiv](https://arxiv.org/html/2607.26072)
- **MCP4IFC: IFC-Based Building Design using LLMs**. arXiv 2511.05533, 2025 **[preprint]**. More than 50 IfcOpenShell tools exposed over MCP. Scene-query tools return compact structured summaries rather than the raw file, the same pattern as pdf2takeoff's MCP. — [arXiv](https://arxiv.org/html/2511.05533)
- **A Modular Reference Architecture for MCP-Servers Enabling Agentic BIM Interaction**. arXiv 2601.00809, 2026 **[preprint]**. Only existence and scope were verified. — [arXiv](https://arxiv.org/pdf/2601.00809)
- **AI Agent Framework for Dynamic BIM Query via Retrieval-Augmented Code Generation for IFC**. Buildings 16(14):2786, 2026 **[peer-reviewed]**. The agent writes IfcOpenShell code guided by retrieved examples instead of querying a fixed data layer. — [DOI](https://doi.org/10.3390/buildings16142786)
- **Visual Sketchpad: Sketching as a Visual Chain of Thought for Multimodal Language Models**. Hu et al., NeurIPS 2024 **[peer-reviewed]**. Giving GPT-4o drawing and specialist-vision tools (detection boxes, segmentation masks) yields +12.7% average on math tasks and +8.6% on vision tasks (V*Bench +14.3%). General evidence that tool-grounded perception beats pure-pixel reasoning. — [NeurIPS paper](https://proceedings.neurips.cc/paper_files/paper/2024/file/fb82011040977c7712409fbdb5456647-Paper-Conference.pdf); [arXiv 2406.09403](https://arxiv.org/abs/2406.09403)
- **DeepEyes: Incentivizing "Thinking with Images" via RL**. arXiv 2505.14362, 2025 **[preprint]**. An RL-learned zoom/crop tool gives a 7B model 90.1% (+18.9) on V* and +6.3/+7.3 on HR-Bench-4K/8K. A follow-up remote-sensing study observed "tool usage homogenization" (the zoom tool invoked on every question). Relevant to high-resolution sheets, where a crop/zoom tool helps perception, but not to numeric extraction. — [arXiv](https://arxiv.org/abs/2505.14362)
- **Drawing-Checker** (see Q4) **[peer-reviewed]**: breaking full-image prompting into detector-matched view pairs before calling the MLLM cut hallucination to 1.5%. A structural decomposition tool improved the VLM. — [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S2212827126008085)

### Inferences
- Taken together, Handoff-H1 (vendor), AEC-Bench (vendor) and Visual Sketchpad (peer-reviewed) indicate that **specialised tools plus orchestration add 20-30 points over a frontier model with generic tools**. All three AEC sources have a commercial interest, though, and no independent replication exists.
- Even the best system (H1) loses to human estimators on quantity precision (P@.25 78.8 vs 87.9). Detection and coverage is where AI helps; exact quantities still benefit from deterministic measurement and review. This supports pdf2takeoff's split: the agent finds items, and the tools measure them.
- The BIM literature's "unit handling and value faithfulness is the bottleneck" finding maps directly onto pdf2takeoff. MCP results should carry explicit units, scale provenance and source coordinates so the agent cannot mis-transcribe them.

### Gaps
- No ablation found that isolates "same model, with vs without deterministic geometry tools" on drawing takeoff. Handoff's per-layer ablation was not retrievable, and AEC-Bench's H vs H+N is the closest available comparison.
- No peer-reviewed LLM-agent QTO paper on 2D PDF drawings was found. All agent-takeoff evidence is vendor preprints.

## Q3. End-to-end automated takeoff systems: academic evaluations and commercial approaches

### Takeaway
Academic end-to-end 2D takeoff evaluated against human quantities remains rare. The best independent evidence is a 2026 ASC case study of Togal.AI on a live commercial project. It found count items near-perfect but **systematic underestimation of area items**, with exterior finishes worst. Recent academic systems mostly report recognition metrics (mAP, IoU), not quantity error. Commercial accuracy figures (98-99%+) are vendor claims with undisclosed methods. Several describe human-QA'd deliverables, not raw AI output.

### Cited Findings

**Academic / independent**
- **Testing AI Accuracy in Quantity Takeoff: A Methodological Case Study in Commercial Construction**. Sadeh, Geloso, Todorov, Proc. Associated Schools of Construction 62nd Annual Int'l Conference, Jun 2026 **[peer-reviewed conference]**. Togal.AI against contractor takeoffs on a live project, 29 line items (exterior/floor/ceiling finishes, windows, doors). Deviations were small but statistically significant, with "consistent underestimation for area-based quantities" and "near-perfect alignment for count-based items". Ceilings were most consistent and exterior finishes deviated most. AI performs best on "repetitive, clearly bounded, and orthogonal elements". Estimator oversight remains essential. — [EasyChair](https://easychair.org/publications/paper/pkrRp)
- **LLM-Integrated Semantic Deep Learning Framework for Automated Floor Plan Analysis, Area Estimation, and Compliance Assessment of Existing Buildings**. Applied Sciences 16(13):6290, 2026 **[peer-reviewed]**. YOLOv8 reaches 92.3% mAP50 (Faster R-CNN 87.2%) and 95.71% in-domain mIoU (82.4% for CubiCasa5K fine-tuned). Recognition metrics reported; quantity-level error not confirmed. — [DOI](https://doi.org/10.3390/app16136290)
- **FloorplanVLM: A Vision-Language Model for Floorplan Vectorization**. Beike, arXiv 2602.06507, Feb 2026 **[preprint]**. Image-to-JSON sequence generation, trained SFT then GRPO for geometric alignment on Floorplan-2M / HQ-300K. 92.52% external-wall IoU on the authors' open FPBench-2K, and handles non-Manhattan layouts. Notable as a VLM emitting **structured geometry** that downstream code measures, rather than numbers. — [arXiv](https://arxiv.org/abs/2602.06507v1)
- **SALI-FP: Evidence-gated multimodal parsing and vectorization of architectural floor plans**. Chen, Wang et al. (Tsinghua), arXiv 2609.25615, Sep 2026 **[preprint]**. Separates "contextual interpretation" (the model) from "authorization to change the drawing": every local revision must be checked against image evidence. A production audit of 11,534 plans gave 752,510 valid polygon objects, plus a 30-case visual evidence set covering openings, oblique boundaries and circulation. No headline accuracy retrieved. — [arXiv](https://arxiv.org/abs/2609.25615)
- **Automatic floor plan analysis: Datasets, methods, and applications (2000-2025)**. Xu, Jha, Mehadi, Mandal, Automation in Construction 178:106378, 2025 **[peer-reviewed survey]**. Supersedes Pizarro 2022 (already cited) as the field map. — (citation via search extraction; no direct link retrieved)
- **BIM-based quantity takeoff: Current state and future opportunities**. Alathamneh, ..., Azhar, Automation in Construction 165:105549, 2024 **[peer-reviewed review]**. BIM-side state of practice. — (citation via search extraction)

**Commercial (all [vendor claim] unless noted)**
- **Togal.AI**: ML detects and measures rooms, walls and openings, then estimators correct the result. Claims "5x faster" and "up to 98% accuracy" on floor plans. A vendor-hosted University of Kansas comparison against On-Screen Takeoff reports quantities within 5% and about 1 min AI plus about 30 min correction versus about 2.5 h manual, but it assumes the manual baseline is correct. — [Togal blog](https://www.togal.ai/blog/ai-takeoff-software-beats-manual-calculations); [Togal case study](https://www.togal.ai/case-study/peer-reviewed-study-togal-ai-vs-on-screen-takeoff)
- **Beam AI (Attentive.ai)**: claims "99%+ accurate takeoffs & estimates in 24-72 hours". This is a **human-QA'd done-for-you deliverable**; a self-serve AI-only mode is credited with about 90% feature capture. No method is disclosed. — [Attentive.ai](https://www.attentive.ai/); [Bildrix analysis (third party)](https://bildrix.com/research/ai-takeoff-accuracy)
- **Kreo**: AI takeoff for rooms, walls, doors and windows, plus auto symbol counting (Pro tier). "Caddie" is described as an agent that performs measurements, annotations, reports and exports on drawings. The agentic-workflow page claims "expert quality of 94.5-98.5%" with no dataset disclosed. — [Kreo pricing](https://www.kreo.net/pricing); [Caddie help article](https://help-takeoff.kreo.net/en/articles/7895351-caddie-%E2%80%94-ai-agent-in-kreo); [Bildrix analysis](https://bildrix.com/research/ai-takeoff-accuracy)
- **Bluebeam Max** (shown at Unbound Oct 2025, global launch May 2026): a premium Revu tier with **Revu + Anthropic Claude via MCP** (natural-language automation over markup data), "Magic Markups" (Duplicate as / Convert to / Offset to cut repetitive takeoff redrawing), "Smart Overlay" (cross-set and cross-discipline change spotting, partly in preview), "Smart Review" (design-gap detection) and stitching. Bluebeam-aligned guidance says Max output should not be treated as final bid quantities without review, and that it organises existing markup data rather than detecting quantities itself. — [Bluebeam press release](https://press.bluebeam.com/2026/05/bluebeam-max-launches-globally-bringing-ai-powered-productivity-to-aec-teams-everywhere/); [Unbound 2025 release](https://press.bluebeam.com/2025/10/bluebeam-unveils-bluebeam-max-next-generation-ai-powered-innovations-at-unbound-2025/); [IMAGINiT reseller blog](https://resources.imaginit.com/building-solutions-blog/how-estimators-can-use-bluebeam-max-to-support-faster-takeoffs)
- **Handoff H1**: launch materials claim it is "ahead of human estimators (77.6%) and ~20 points clear of the best frontier model". Paper caveats are in Q2. — [YC launch](https://www.ycombinator.com/launches/RdZ-handoff-h1-a-takeoff-model-that-outperforms-human-estimators)
- Third-party critique: vendor percentages are not comparable. Togal's figure is qualified "on floor plans", and Beam's ±1% describes a human-reviewed deliverable. — [Bildrix](https://bildrix.com/research/ai-takeoff-accuracy)

### Inferences
- Bluebeam Max is now the closest commercial analogue to pdf2takeoff's MCP design (Claude driving a PDF tool over MCP). Its published scope is markup automation over human-drawn data, not deterministic auto-count or measure tools. pdf2takeoff's differentiator is tool-sourced counts and measurements.
- The ASC finding that areas are systematically underestimated while counts are accurate suggests area tools should expose their boundary convention (wall centreline, inside face or outside face) and gap-closing parameters in results. Some "AI error" is likely a convention mismatch. This is an inference; the paper does not attribute the cause.
- The coverage and P@.25 metrics (Handoff) and count exact-match plus MAPE (AECV-Bench) are the emerging evaluation vocabulary. Area and length need an analogous metric, such as relative error per line item.

### Gaps
- No independent, multi-project, multi-tool accuracy comparison with a published error table exists. Bildrix notes several "tests" name no organisation and publish no table.
- Autodesk Takeoff (AutoCount) and STACK AI approaches were not found in this sweep.
- Togal's and Kreo's model architectures are not publicly documented beyond "ML segmentation/detection".

## Q4. Drawing revision comparison: raster overlay, vector diff, learned change detection

### Takeaway
There is still no peer-reviewed learned change-detection method for drawing revisions. The 2024-2026 additions are (a) a peer-reviewed VLM-RAG drawing comparator (Drawing-Checker, Procedia CIRP 2026) that works only after deterministic view matching, (b) a documented vector-PDF primitive-diff recipe (practitioner, not peer-reviewed), (c) commercial "smart overlay" features, and (d) general benchmarks showing VLMs miss most fine-grained changes. The literature supports deterministic diff first, with an optional VLM explaining matched regions.

### Cited Findings
- **Drawing-Checker: A Vision RAG Framework for Automated Comparison of Engineering Drawings**. Zhou, Camba, Company, Contero, Procedia CIRP 142:127-132, 2026 (36th CIRP Design Conference), DOI 10.1016/j.procir.2026.05.235 **[peer-reviewed]**. The pipeline retrieves the nearest reference drawing by CLIP embedding, detects views with YOLO, pairs views and flags unmatched ones, then sends matched crops to an MLLM (Azure OpenAI) for annotation and geometry discrepancies. Output is a structured report plus overlays. On 500 test cases it beats full-image prompting on precision, recall and F1. The view-matched strategy reports P 0.985, R 0.917, F1 0.950 and a 1.5% hallucination rate (ResearchGate table, secondary). Stated weaknesses: geometric reasoning, localisation and hallucination control. Mechanical drawings against reference standards, not old-versus-new AEC revisions. — [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S2212827126008085); [GitHub](https://github.com/Hiram31/Drawing-Checker); [ResearchGate results table](https://www.researchgate.net/figure/Summary-of-Visual-Reasoning-Experiments_tbl1_406593809)
- **PDF Drawing Diff (vector)**. Boardflare template **[practitioner/vendor documentation, not peer-reviewed]**. Works on CAD-exported vector PDFs without rasterizing. It extracts primitives with PyMuPDF, registers the pages to remove offsets, drops unchanged primitives, then classifies the rest as exact / moved / fuzzy / added / modified. Change regions are grouped because "one engineering object may be exported as many PDF paths", so the region is the review unit. Example output: 15 exact, 1 moved, 3 fuzzy, 2 added, 4 modified, 2 change regions. — [Boardflare](https://www.boardflare.com/templates/pdf-drawing-diff/)
- **AutoCAD DWG Compare** **[vendor documentation]**: entity-level diff with common objects in grey, comparison-only objects in red and current-only objects in green. Changes are grouped by proximity into revision-cloud "change sets". This is the native-CAD baseline UX. — [Autodesk Help](https://help.autodesk.com/cloudhelp/2021/ENU/AutoCAD-LT/files/GUID-2D69E78D-5C82-464F-B864-CD29D5720EB9.htm)
- **3DViewStation / CADInterop** **[vendor claim]**: compares DWG/DXF entities and technical PDFs, with automatic alignment correcting scale and position offsets, and detects dimension and annotation changes. — [CADInterop](https://www.cadinterop.com/en/your-needs/analyze-cad-models/a-powerful-and-safely-solution-to-compare-drawing.html)
- **Bluebeam Max Smart Overlay** **[vendor claim]**: change and discrepancy spotting across whole sets and disciplines. — [Bluebeam press release](https://press.bluebeam.com/2026/05/bluebeam-max-launches-globally-bringing-ai-powered-productivity-to-aec-teams-everywhere/)
- **Raster pipeline practice** **[practitioner blog]**: align, pixel diff, ROI compare, OCR of notes, token diff. Even small shifts create false differences, so registration is critical. — [Medium (R. Gopal)](https://ramugopal.medium.com/automated-engineering-drawing-comparison-using-computer-vision-and-ocr-95d66bf3fbaf)
- **VLMs on change spotting**: DiffSpot best recall is 40.7% (hard tier under 23%) [preprint]; VDiff-Bench shows a "no difference" bias up to 80.9% [preprint]. — [DiffSpot](https://arxiv.org/html/2605.29615); [VDiff-Bench](https://paperswithcode.co/paper/2609.06245)
- **Learned change detection** exists mainly in remote sensing: Siamese U-Nets and attention variants, with LEVIR-CD and SECOND as datasets. No drawing-revision dataset was found. — [Siamese U-Net CD (IEEE)](https://ieeexplore.ieee.org/document/9733219/); [SECOND / asymmetric Siamese (IEEE)](https://ieeexplore.ieee.org/document/9555824/)

### Inferences
- The best-supported design for `compare_revisions` is tiered. First register (transform estimation). Then do a vector primitive diff when both PDFs are vector (exact / moved / fuzzy / added / modified), plus a text-layer token diff. That classifies changed dimensions as "value changed" rather than "pixels changed". Raster XOR overlay is the fallback for scans. Group changes into regions the way AutoCAD change sets do. Optionally let a VLM caption each grouped region the way Drawing-Checker does, never asking it to find changes.
- For takeoff the valuable output is **quantity delta**: re-run saved count and measure items on the new revision and report the differences. No paper addresses this, so it is a differentiator rather than a catch-up item (inference).

### Gaps
- No peer-reviewed AEC revision-diff method or benchmark dataset (old/new sheet pairs with change masks) was found for 2022-2026.
- Smart Overlay's method (raster versus vector, learned or not) is undisclosed.

## Q5. Recommendations for pdf2takeoff's MCP/agent design and evaluation

### Takeaway
pdf2takeoff should keep its deterministic-numbers rule (now backed by AECV-Bench, MeasureBench, LED-BENCH, CountQA and AEC-Bench). It should evaluate itself on two public harnesses: the AECV-Bench counting set (agent with pdf2takeoff tools versus the published VLM-only scores) and AEC-Bench (add pdf2takeoff MCP as a harness variant). It should adopt Handoff-style coverage and P@.25 line-item metrics for full takeoffs, and add a vector or text diff tier to `compare_revisions`.

### Cited Findings (basis for each recommendation)
- AECV-Bench publishes 120 floor plans with door, window, bedroom and toilet counts, and scores with exact match and MAPE. The best VLM-only result is about 54% EM and 15% MAPE. This gives a ready baseline that an agent calling `scan`/`count` can be compared against. — [GitHub](https://github.com/AECFoundry/AECV-Bench); [aecv-bench.com](https://aecv-bench.com/)
- AEC-Bench is Apache-2.0, runs in Docker/Harbor and already ships a Claude Code harness. Its H vs H+N design is the template for an "H + pdf2takeoff MCP" ablation. Its intra-sheet tasks (note-callout accuracy, detail titles) and intra-drawing tasks (sheet index, cross-refs) depend on positioned text, which `read_text` provides. — [GitHub](https://github.com/nomic-ai/aec-bench); [arXiv](https://arxiv.org/abs/2603.29199)
- The Handoff-H1 metric design: per line item coverage plus P@.25, composite score, a human-estimator reference row, and expert consensus ground truth. — [arXiv 2608.15032](https://arxiv.org/abs/2608.15032)
- Agents rasterize heavily without benefit (pdftoppm in 96% of Codex runs). — [arXiv 2603.29199](https://arxiv.org/html/2603.29199v1)
- Zoom tools get over-invoked ("tool usage homogenization"). — [DeepEyes / follow-ups](https://arxiv.org/abs/2505.14362)
- VLMs read digits but misplace positions relative to scale (MeasureBench). — [CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/papers/Lin_Do_Vision-Language_Models_Measure_Up_Benchmarking_Visual_Measurement_Reading_with_CVPR_2026_paper.pdf)
- BIM agents: unit handling and value faithfulness are the bottleneck. — [Zenodo](https://zenodo.org/records/22679659)
- SALI-FP: separating model interpretation from authorization to change geometry. — [arXiv 2609.25615](https://arxiv.org/abs/2609.25615)

### Inferences (recommendations)
1. **External eval A: AECV-Bench counting.** Run an MCP agent (render, identify one exemplar, `scan`/`count`) on the 120 plans. Report EM and MAPE against the published VLM-only leaderboard. This is the cheapest credible public proof that tool grounding beats pixel reading. Check the dataset licence first. Note that the plans are probably raster images, which exercises the raster scan tier rather than the text layer.
2. **External eval B: AEC-Bench harness.** Add an "H+P" configuration: the Claude Code harness plus the pdf2takeoff MCP server (`read_text`, `render_page`, `compare_revisions`). Compare against the published H and H+N numbers on intra-sheet and intra-drawing tasks. This reproduces Nomic's ablation design on a third-party benchmark.
3. **In-house "TakeoffBench-lite".** For full takeoffs on the repo's sample sets, score each line item for coverage, and for quantity use P@.10 / P@.25 plus MAPE for counts. Include a human-estimator row. Keep areas and lengths separate from counts, because the ASC Togal study shows they fail differently.
4. **Fill the measurement-benchmark gap.** No public benchmark tests VLM length or area measurement on scaled drawings (Q1 gap). A small synthetic set from the existing generator would do it: known scale, known wall lengths and room areas, and the question "what is the area of room X". Evaluate VLM-only against agent-plus-tools. This is publishable as a niche contribution (inference).
5. **Tool-result provenance.** Every numeric MCP result should carry `{value, unit, scale_source (text-layer | user-calibrated | OCR), source_bbox, method}`. The BIM literature shows unit and value transcription is where agents fail. Provenance also lets a VLM-as-judge (Ghosh, already cited) audit results.
6. **Discourage blind rasterization.** Tool descriptions should steer agents to `read_text` and geometry first, with `render_page` only for locating things (AEC-Bench evidence). Consider making `render_page` return text-layer word boxes alongside the image.
7. **`compare_revisions` tiers.** Register, then vector primitive diff (exact / moved / fuzzy / added / modified), then text-token diff (dimension and value changes), then raster overlay fallback, grouped into change regions. Add a quantity-delta mode that re-runs saved takeoff items on the new revision. Do not ask the VLM to find differences (DiffSpot / VDiff-Bench). Optionally let it caption grouped regions (Drawing-Checker pattern).
8. **Authorization separation (SALI-FP pattern).** The agent may propose takeoff items, but only tool calls create quantities. Agent-proposed polygons should be validated against ink evidence by the deterministic engine before they count. pdf2takeoff largely does this already; making it explicit in the MCP spec is cheap.
9. **Positioning versus Bluebeam Max.** Max is the commercial "Claude over MCP in a PDF tool". Its published AI scope is markup automation and organising existing markup quantities. pdf2takeoff can claim deterministic auto-count, measure and diff tools that the agent calls. Revisit as Max evolves.

### Gaps
- Licence terms for the AECV-Bench data were not verified. The AEC-Bench code is Apache-2.0, but the underlying drawing licences were not checked.
- No evidence was found on how pdf2takeoff-style vector-PDF tools would score on AEC-Bench, so recommendation 2 is a proposed experiment, not a known result.
